# OTDwx documentary media workflow — production v1

**Purpose:** Make visually memorable, historically honest X posts with sourced photos,
maps and radar, not repetitive stock-style infographics or invented archival imagery.
Each post gets one compelling visual treatment, not every possible asset.
This procedure is a research and export gate; **only a human can approve/schedule**.

## Visual decision / formats

| media_mode | When | Export behavior |
| --- | --- | --- |
| `graphic_only` | The data or explanation is the story | The existing themed SVG/PNG |
| `graphic_plus_photo` | Strong verified event/aftermath photo | Base graphic plus a cleared photo; optional original-photo editorial split |
| `graphic_plus_map` | Track, impact boundary or observing network is essential | Graphic plus sourced local map file (or source-backed map generated by OTDwx) |
| `carousel` | 2–4 complementary **still** images best tell the event | Base graphic plus up to three independently cleared still assets |
| `animated_package` | Observed radar/satellite evolution tells the story | Base graphic and one genuine GIF loop as a separate posting option; never imply it can be combined with photo attachments in one X composer |

For `graphic_plus_photo`, `photo_layout: "none"` preserves the original
photograph in a separate asset; `photo_layout: "editorial_split"` creates an
additional 16:9 OTDwx photo-led SVG and (with `--png`) PNG. The documented
photo fills its allotted space using **contain**, not a crop. The extra composite
only renders when modification/adaptation is explicitly allowed. Both formats
carry credit and descriptive alt text in the private output manifest.

Visual signature: OTDwx masthead, event date, source, restrained hazard-specific
colors, and typographic discipline. Composition changes with the source data.
Do not add generic AI atmospheric photos, fabricated maps, synthetic radar,
NOAA/NWS insignia, invented "archive" labels, or fake geographic certainty.

## Asset-specific review before any export

**Finding a picture on an agency page is not rights clearance.** Some
government websites host third-party photos. Record a rights-basis URL and
check the *individual* asset, photographer, licensing conditions, crop rules
and attribution. NOAA/NWS-only content is generally public-domain unless
marked otherwise, but do not infer clearance for a submitted photograph.

Candidate source priorities: NWS/NHC/NOAA-origin material with documented
rights; USGS; NASA (specific usage rules); other public agencies; Commons
with verified file-specific CC BY/CC0 information; archives with clear
licenses or documented permission. Unclear rights means **do not export**.

Every real supplementary asset needs the fields below (in the private
package and mirrored to **Media Asset Registry** in Sheets):

- `kind`: photo, map, radar_loop, satellite_loop, radar_still, satellite_still, newspaper, other
- `file`: an actual **relative local file path**, not a URL, safely inside `--asset-root`
- `source_url`, `rights_basis_url`, `creator`, `credit`, `caption`, `alt_text`
- `rights_status`: public_domain, government_reusable, cc_by, licensed,
  permission_granted, original_work (only **after** an asset-specific human review)
- `rights_reviewed_by`, `rights_reviewed_on` (YYYY-MM-DD)
- `commercial_use_allowed: true` and `credit_placement_confirmed: true`
  must be explicitly verified, not guessed; `modifications_allowed` is a boolean
- For photos: `event_relation` = during_event, aftermath, related_context.
  A context photo also needs `context_disclosure` explicitly saying it does
  **not** show the named historical event.
- CC BY: retain `license_url`; when creating a composite, include
  `changes_disclosed: true`, and show proper author, license and modifications
  in visible credit and/or the post's accompanying information. For licensed
  or permission-granted assets record `license_scope` describing coverage.
- The generator does not independently verify rights assertions. Human
  reviewers must ensure the required **full** credit or license references
  actually appear with the final X publication.

Unknown, researching, denied, rights-uncertain, invalid, or unreviewed
assets are **blocked from production export**. Research candidates may
remain in Sheets with those statuses.

## Private JSON input / reproducibility

See `data/schema/media-package.schema.json` for the media-package
machine-readable fields. Keep the full package, source photo bytes, consent
documents, and unpublished visual drafts **out of this public GitHub repo**.

Start from the same core event format already accepted by
`python -m otdwx.production`, and add the following **only after
asset-specific review**:

```json
{
  "media_mode": "graphic_plus_photo",
  "media_editor_approval": "pending",
  "photo_layout": "editorial_split",
  "photo": {
    "kind": "photo",
    "file": "photos/private-confirmed-event.jpg",
    "source_url": "https://example.org/individual-photo-page",
    "rights_basis_url": "https://example.org/individual-license-or-permission",
    "creator": "Actual photographer after verification",
    "credit": "Actual photographer / actual archive",
    "caption": "Exact place, event/aftermath and date after verification",
    "alt_text": "Human-written description of the actual photographed scene and its significance.",
    "event_relation": "aftermath",
    "rights_status": "permission_granted",
    "rights_reviewed_by": "Human reviewer",
    "rights_reviewed_on": "2026-11-21",
    "license_scope": "Documented permission to repost and compose on the OTDwx account",
    "commercial_use_allowed": true,
    "modifications_allowed": true,
    "credit_placement_confirmed": true
  }
}
```

**This is structural example data, not proof that any such photo or permission
exists. Do not publish it as written.** Keep all normal event keys
(`event_id`, `event_date`, `post_date`, `caption`, `source_name`,
`source_url`, `evidence`, `alt`, `type`, `graphic_spec`) from the main
production package.

### Commands

```bash
python -m pip install -e .
python -m pip install cairosvg  # only for PNG export
python -m otdwx.production \
  --input /private/otdwx/approved-for-layout.json \
  --asset-root /private/otdwx/cleared-media \
  --output /private/otdwx/exports \
  --png
python -m unittest discover -s tests -v
```

All file paths are resolved under the given root. Absolute paths, directory
traversal, unapproved media, unsupported extensions and missing files block
the export. Photo and map bytes are **copied as supplied** rather than
auto-enhanced; composite SVG has a base64-embedded local JPEG/PNG with
a clearly identified actual source. No web fetching or external SVG links.

The new private `<date>_<event_id>.media.json` export describes each
asset's credit, caption, alt text, rights-basis URL and event relationship.
It explicitly records `publishing_enabled: false` and `approval: pending`.
The existing caption/graphic exports are preserved.

## Connected editorial sheet

- `Media Asset Registry`: a separate row **per possible photo/map/loop**,
  including leads with uncertain rights. Preserve the original source URLs,
  individual creator, license proof and actual reviewer. The rights-gate
  formula is a convenience **not a substitute for human legal review**.
- `Post Studio`: `Media Mode`, `Selected Media Asset ID`, `Media Gate`,
  `Media Approval`, `Private Package Link` supplement the existing draft.
- `Reverse Production Queue`: the media selection and media approval
  columns identify what is outstanding for each planned date.

**No automatic sync** exists between the spreadsheet and local private
asset folders. Only an actual reviewer can mark media approval. Do not
change the X Schedule Status until the platform confirms the schedule.

## Special cases

- Real historic newspaper scans may carry independent typography, image,
  digitization and underlying photo rights. Screenshot reuse requires review.
- If the asset portrays an **analogous storm or generic aftermath** rather
  than the exact event, mark it `related_context` and clearly disclose that.
  Prefer an actual event photo or no photo to misleading context.
- Radar/satellite loops should be built from authentic, time-ordered inputs
  with station/product/time metadata via the existing `radar_loop.py`.
  Never treat a simulated demonstration GIF as archived observation.
- A photo can be a main image instead of accompanying a chart when its
  documentary impact is stronger. Branding can stay in the caption/alt text
  or a restrained editorial label; the picture should remain the hero.
- Final posting workflow: check scientific facts; review all rights;
  inspect crops, text and alt text; manually approve; schedule in X;
  record the real X confirmation/link.

These links explain broad rules, but do not establish reuse rights for
any individual photograph or newspaper scan.
