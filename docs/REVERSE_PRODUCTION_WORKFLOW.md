# OTDwx — Reverse chronological first-year production

**First 365-post planning interval:** 2027-11-20 → 2026-11-21, inclusive.
This is a *production order*, not a publication order. Posts publish daily in
ordinary chronological sequence if they are actually scheduled. A subsequent
leap-year cycle includes February 29; do not manufacture a Feb 29 in this span.

## Private source of truth

[OTDwx Editorial Desk — Reverse Production Queue](https://docs.google.com/spreadsheets/d/1H9BhGYY3FUmdr78sAuK47SQJEyHozyf_FdC5gYlgZzw/edit#gid=773617556)

That tab is seeded with 365 provisional Phase A candidates, one for every
publication date. Some already have private drafts and original illustrations
in Post Studio. A provisional candidate is NOT approved content.

For each date, work backwards one row at a time:

1. **Select** the most distinctive sourced primary or alternate event for that
   exact anniversary; check hazard, region, decade, and source repetition.
2. **Verify** event-date convention; numerical claims and observation scope
   against primary documents; identify common underlying data, estimates, and
   any editorial uncertainties.
3. **Compose** one human-readable #OTDwx post with the historic date in the
   header and meaningful source credit. Use the repository post checker,
   keeping the standard X length <=280 weighted characters (aim <=260).
4. **Prepare original visual evidence** from checked data: edited vector charts,
   labeled maps, or genuine licensed archives. No fabricated radar, tracks,
   photos, or unlabeled reconstructions. Record individual image rights and
   meaningful alt text.
5. **Store unpublished artifacts privately** (Post Studio and private Drive).
   The GitHub repository is public; do not commit unpublished captions,
   original graphic files, unreleased schedules or credentials here.
6. **Human editorial approval** only after final copy, sources, graphics,
   alt text and rights have actually been reviewed. 'Source core paired' or
   'Draft prepared' must never be equated with approval.
7. **Schedule** the approved post manually in X or an authorized publishing
   integration; check the account's actual allowed scheduling horizon and
   timezone. Only after provider confirmation may the queue move to
   'Scheduled' and record the exact Eastern posting time.
8. **Verify publication** on the release date and store the actual post URL
   and exact text in Publishing History. Do not pre-fill published URLs.

## Queue columns and semantics

- A–H: target publishing date, anniversary, research candidate and provenance.
  These are provisional research leads, not signed-off final selections.
- I: Production Stage, starting at 'Research queued' or 'Draft prepared'.
- J–L: human fact check, graphic/rights review, and approval. All remain
  pending until separately reviewed.
- M: X Schedule Status, initially 'Not scheduled' for every row.
- N: actual intended Eastern posting time, unset until decided.
- O: private visual link, available for prior prepared drafts only.
- P: actual published post URL (never a forecast/guess).
- Q: editorial notes and source cautions.
